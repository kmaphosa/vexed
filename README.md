# VEXed — is this CVE actually my problem?

Dependency scanners tell you that you have 40 CVEs. They don't tell you which ones
your code can actually reach. Developers end up either ignoring the whole list or
burning days upgrading things that never mattered.

**VEXed** triages every vulnerability in your dependency tree against *your* source code:

1. **Find** known vulnerabilities for every pinned dependency (via [OSV.dev](https://osv.dev)).
2. **Prioritise** them using real-world exploitation data: [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)
   (exploited in the wild now) and [FIRST EPSS](https://www.first.org/epss/) (probability of exploitation).
3. **Check reachability** with **NVIDIA Nemotron on Nebius Token Factory**. This runs as a two-step loop:
   - Nemotron reads the advisory and names the vulnerable functions and modules (e.g. `yaml.load` + `FullLoader`).
   - VEXed searches your code for import sites and call sites of exactly those APIs.
   - Nemotron weighs the evidence and returns a verdict (**affected**, **not affected** with a reason,
     or **needs review**) that cites `file:line` and gives a concrete next step.
4. **Export** the result as an [OpenVEX](https://openvex.dev) document. Scanners such as Trivy and Grype
   can consume it to suppress the noise automatically.

## Using NVIDIA and Nebius

| What | How |
|---|---|
| Model | An **NVIDIA Nemotron** open model (set with `NEBIUS_MODEL`; if unset, VEXed picks the first Nemotron text model it finds on your account) |
| Inference | **Nebius Token Factory**, OpenAI-compatible endpoint `https://api.tokenfactory.nebius.com/v1/` |
| Calls | Two per vulnerability: symbol extraction, then a reachability verdict. Temperature 0, responses cached, up to 6 run concurrently |
| Fallback | Without an API key, VEXed runs in heuristic mode. This is clearly labelled in the UI and is useful for comparing results with and without the model |

## Supported inputs

- `requirements.txt` (only `==` pins can be checked; unpinned packages are listed in the report)
- `package-lock.json` (v1–v3)
- CycloneDX or SPDX JSON SBOMs (any ecosystem with a purl, e.g. generated by `syft dir:. -o cyclonedx-json`)
- Source code as a `.zip` or a public GitHub URL. If you give a GitHub URL, the manifest is found automatically.

## Run it

```bash
git clone https://github.com/kmaphosa/vexed && cd vexed
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
export NEBIUS_API_KEY=...            # from https://tokenfactory.nebius.com
# optional: export NEBIUS_MODEL=<exact Nemotron model id from your console>
python app.py                        # http://127.0.0.1:7860
```

In the UI, click **Try the demo app**. This scans `examples/vulnerable-app/`, a small Flask service with
deliberately outdated pins, and shows a CRITICAL PyYAML CVE flagged as *affected* (the app feeds request
bodies to `yaml.load(..., Loader=yaml.FullLoader)`). The report also shows how each of the other CVEs in the tree was judged.

### Tests

```bash
pip install pytest && python -m pytest -q
```

The tests mock all network calls (OSV, EPSS, KEV, LLM), so they run offline.

### Deploy to Hugging Face Spaces

Create a Gradio Space, push this repo to it, and add `NEBIUS_API_KEY` (and optionally `NEBIUS_MODEL`)
as **secrets** in the Space settings.

## How it works

```
manifest ──► parsers ──► OSV.dev ──► EPSS + CISA KEV ─┐
                                                      ▼
source code ──► codebase search ◄── Nemotron: "which APIs are vulnerable?"
                      │
                      ▼
               Nemotron: "given this evidence, is the app affected?"
                      │
                      ▼
        ranked report (P0–P3)  +  OpenVEX JSON
```

| Module | Responsibility |
|---|---|
| `vexed/parsers.py` | requirements / npm lockfile / CycloneDX / SPDX → packages |
| `vexed/intel.py` | OSV batch query, GHSA/PYSEC de-duplication, EPSS, KEV |
| `vexed/codebase.py` | zip (zip-slip safe) or shallow git clone; import and symbol search |
| `vexed/llm.py` | Nebius client, prompts, strict JSON parsing, VEX normalisation |
| `vexed/pipeline.py` | concurrent triage, prioritisation, OpenVEX and Markdown output |

## Limitations

- Reachability comes from static text search plus LLM judgement. It is not a full call graph.
  Treat **not affected** as a strong hint, and review it before publishing VEX to customers.
- Transitive dependencies that your code never imports directly are usually marked **needs review**,
  because another library may call them.
- Only public GitHub repositories are supported for URL input.
